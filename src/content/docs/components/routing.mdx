Routing in NaN is handled by the `NaN\Application\Middleware\Router` namespace.
All routers are PSR-15-compatible middleware.
The default way to register routes in NaN is with the `RoutesCollection` router and `Route` classes.
The `Route` class is also a PSR-15-compatible middleware.

## Installation

Comes packaged with the [application](/nan-docs/components/application/) component.

## RoutesCollection

```php
use NaN\Application\Middleware\ClosureMiddleware;
use NaN\Application\Middleware\Router\{
	Route,
	RoutesCollection,
};
use NaN\Collections\Middleware\MiddlewareCollection;
use Psr\Http\Message\ResponseInterface;

$router = new RoutesCollection(
	new Route(
		'/posts', // static path
		new ClosureMiddleware(
			function (): ResponseInterface {}, // handler
		), // middleware
		'posts', // name
	),
	new Route(
		'/posts/{id}', // parameterized path
		new ClosureMiddleware(
			function (int $id): ResponseInterface {}, // handler
		), // middleware
		'post', // name
	),
);
```

Internally, `RoutesCollection` uses a radix trie.
Performance-wise, there shouldn't be any concerns.
Benchmark results measure registering 1000 routes occurring in about 1 millisecond,
and looking up a single route occurs within microseconds, whether static or parameterized.

When using parameterized routes,
the part within the curly brackets is the parameter's name.
The parameter name must obey PHP variable naming rules,
since they will be autowired into their handlers.
They can also be accessed from the from the request's query parameters.

Parameters are made simple by design, requiring the parameter to fill its entire space.
This means the path `/page-{page}` is invalid and will not generate the result you hope for.
The proper way to do it is `/page/{page}`.

Static routes will take precedence over parameterized routes.
So, you should construct your parameterized routes while being conscious of your static routes.

### Request validators

Using closures for route handlers will match against every HTTP method.
To have routes match only against certain HTTP methods
you can use request validators provided by the `NaN\Http` namespace as route middleware.

```php
use NaN\Application\Middleware\ClosureMiddleware;
use NaN\Collections\Middleware\MiddlewareCollection;
use NaN\Http\Request\Validators\GetRequestValidator;

$route = new Route(
	'/',
	new MiddlewareCollection(
		new GetRequestValidator(),
		new ClosureMiddleware(
			function () {}, // handler
		),
	), // middleware
);
```

For more information on request validators, see the [http](/nan-docs/components/http/) component.

### Controllers

To have fine-tuned control over multiple HTTP methods, you'll need to make use of controllers.
NaN provides several interfaces and traits that you should be aware of.

Currently, to create a controller you'll need to implement the `ControllerInterface` interface.
To simplify development, we provide a matching `ControllerTrait` trait.

```php
use NaN\Application\Controller\Interfaces\ControllerInterface;
use NaN\Application\Controller\Traits\ControllerTrait;

class HomeController implements ControllerInterface {
	use ControllerTrait;
}

$route = new Route('/', new HomeController());
```

The `ControllerTrait` trait judges your controllers by the controller interfaces they implement.
It also provides placeholder methods for `GET` and `HEAD`.

The following interfaces, along with their matching traits, are available.

```php
use NaN\Application\Controller\Interfaces\{
	ControllerInterface,
	ConnectControllerInterface,
	DeleteControllerInterface,
	OptionsControllerInterface,
	PatchControllerInterface,
	PostControllerInterface,
	PutControllerInterface,
	TraceControllerInterface,
};
use NaN\Application\Controller\Traits\{
	ControllerTrait,
	ConnectControllerTrait,
	DeleteControllerTrait,
	OptionsControllerTrait,
	PatchControllerTrait,
	PostControllerTrait,
	PutControllerTrait,
	TraceControllerTrait,
};
```
### Dependency injection

The [application](/nan-docs/components/application/) component autowires dependencies into routes.
Unlike controllers, closures do not need to set their parameters as optional.
